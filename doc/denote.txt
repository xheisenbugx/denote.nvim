1. INTRODUCTION                                                 *denote-intro*

`denote.nvim` is a pure-Lua Neovim implementation of Protesilaos Stavrou's
Emacs Denote package. It requires no external database, no tree-sitter parser,
and no external binaries. Everything is driven by plain-text files and a
predictable, human-readable, machine-parsable file-naming scheme.

Because it reads and writes the exact same filenames, front matter, and
`denote:` links as Emacs Denote, you can share one notes directory seamlessly
between Emacs and Neovim—and pair it directly with `org.nvim` for Org files
or use Markdown (YAML/TOML) and plain text out of the box.

==============================================================================
2. INSTALLATION & SETUP                                         *denote-setup*

With lazy.nvim: >lua
  {
    "xheisenbugx/denote.nvim",
    opts = {
      directory = "~/Documents/notes",
      file_type = "markdown-yaml", -- or "org", "markdown-toml", "text"
      known_keywords = { "emacs", "neovim", "philosophy", "work" },
    },
  }
<

Run `:checkhealth denote` to verify your setup, picker backend, silos, and
`org.nvim` integration.

3. FILE-NAMING SCHEME                                          *denote-naming*

Every Denote file follows the canonical scheme: >
  DATE==SIGNATURE--TITLE__KEYWORDS.EXTENSION
<
  DATE        Unique timestamp identifier `YYYYMMDDTHHMMSS` (immutable ID).
  ==SIGNATURE Optional Folgezettel / sequence string (e.g. `1a`, `1=2`).
  --TITLE     Kebab-case sluggified title.
  __KEYWORDS  Underscore-separated sorted keyword tags.
  .EXTENSION  `.org`, `.md`, `.txt`, `.org.gpg`, `.pdf`, or any file type.

Components can be reordered via `file_name_components_order`. When
`"identifier"` is not first, it is prefixed with `@@` (Denote 3.x/4.x).

==============================================================================
4. FRONT MATTER & FILE TYPES                              *denote-frontmatter*

Four built-in file types are supported (plus custom entries in `file_types`):

  `org` (`.org`):
    `#+title:`, `#+date:`, `#+filetags:`, `#+identifier:`, `#+signature:`

  `markdown-yaml` (`.md`):
    YAML block (`---`) with `title`, `date`, `tags`, `identifier`, `signature`

  `markdown-toml` (`.md`):
    TOML block (`+++`) with `title`, `date`, `tags`, `identifier`, `signature`

  `text` (`.txt`):
    Key/value header terminated by `---------------------------`

5. COMMANDS                                                  *denote-commands*

`:Denote [subcommand] [args]`                              *:Denote*
  Unified command dispatcher with tab completion. Running `:Denote` with no
  arguments creates a new note.

  Creation:
    `note [title]`              Create a new note
    `open` / `open_or_create`   Open an existing note or create a new one
    `open_with_command`         Open or create choosing creation command
    `type`                      Create a note choosing file type
    `date`                      Create a note with a custom date
    `subdirectory`              Create a note in a subdirectory
    `template`                  Create a note using a named template
    `signature`                 Create a note with a signature
    `:DenoteRegion`             Create a note from visual selection

  Linking & Navigation:
    `link`                      Insert a link to an existing note
    `link_id_only`              Insert an identifier-only link
    `link_or_create`            Link to existing note or create & link
    `link_or_create_with_command` Link or create choosing creation command
    `link_after_creating`       Create a new note and link to it
    `link_to_heading`           Link directly to an Org or Markdown heading
    `link_to_file_with_contents` Link to a note whose contents match a query
    `link_to_all_files_with_contents` Insert links to all notes matching content
    `add_links [regexp]`        Insert a list of links matching regexp
    `follow`                    Follow the `denote:` link under the cursor
    `find_link`                 Pick an outbound link in the current buffer
    `backlinks`                 Open the interactive backlinks split buffer
    `find_backlink`             Jump to a backlinking file via fuzzy picker
    `find_backlink_with_location` Jump directly to a backlink line via picker
    `preview`                   Preview the note behind the link under cursor
    `convert_to_file_links`     Convert `denote:` links to relative file links
    `convert_to_denote_links`   Convert relative file links to `denote:` links

  Search & Explorer:
    `grep [query]`              Full-text search across Denote notes
    `:DenoteGrepRegion [query]` Grep only inside notes referenced in selection
    `query_contents_link [q]`   Insert a live `denote:query-contents:` link
    `query_filenames_link [q]`  Insert a live `denote:query-filenames:` link
    `explorer [regexp]`         Open the interactive Denote explorer buffer
    `sort_dired`                Prompt for regexp & sort key, open explorer

  Capture (`denote-org-capture`):
    `capture [key]`             Create a note from a capture template
    `:[range]DenoteCapture [key]` Same, with the selection as `%i`

  Reports & Maintenance:
    `unlinked_mentions`         Quickfix list of unlinked mentions of this note
    `link_mention`              Turn the mention on the current line into a link
    `check`                     Quickfix list of broken links and orphan notes
    `reindex`                   Drop cached file index, titles, and `rg` check

  Renaming & Front Matter:
    `rename`                    Interactively rename any file + front matter
    `rename_title`              Rename only the title
    `rename_keywords`           Rename only the keywords
    `rename_signature`          Rename only the signature
    `rename_date`               Change the date / identifier
    `rename_identifier`         Directly change the timestamp identifier
    `rename_from_front_matter`  Sync filename on disk from front matter
    `change_file_type [type]`   Convert note + front matter to another file type
    `add_front_matter`          Add front matter to a file lacking it
    `keywords_add [kws...]`     Add keyword(s) to current file
    `keywords_remove [kws...]`  Remove keyword(s) from current file

  Journal (`denote-journal`):
    `journal [date]`            Open or create journal entry for today/date
    `journal_new [date]`        Always create a new journal entry
    `journal_link [date]`       Link to today's (or date's) journal entry
    `journal_calendar [date]`   Month calendar of journal entries

  Sequences (`denote-sequence` / Folgezettel):
    `sequence_parent`           Create new top-level sequence note (`1`, `2`)
    `sequence_child`            Create child sequence note (`1=1` / `1a`)
    `sequence_sibling`          Create sibling sequence note (`1=2` / `1b`)
    `sequence_find`             Fuzzy-pick any sequence note
    `sequence_relatives`        Jump to parent, siblings, children, descendants
    `sequence_link`             Insert link to a sequence note
    `sequence_reparent`         Move current note under a new parent

  Silos (`denote-silo`):
    `silo_create`               Create a note inside a chosen silo
    `silo_open`                 Open or create a note in a chosen silo
    `silo_explorer`             Open explorer in a chosen silo
    `silo_switch [dir]`         Switch active Denote directory for session

  Org Dynamic Blocks (`denote-org`):
    `dblock_links [regexp]`     Insert `#+BEGIN: denote-links` block
    `dblock_backlinks`          Insert `#+BEGIN: denote-backlinks` block
    `dblock_files [regexp]`     Insert `#+BEGIN: denote-files` block
    `dblock_update`             Update all `denote-*` dynamic blocks in buffer

6. KEYMAPS                                                    *denote-keymaps*

All global keymaps live under `mappings.prefix` (default `<leader>n`):

  `<leader>nn`   New note (visual mode: create note from region)
  `<leader>no`   Open or create note
  `<leader>nt`   New note (choose file type)
  `<leader>nd`   New note (custom date)
  `<leader>ns`   New note (subdirectory)
  `<leader>nT`   New note (template)
  `<leader>nS`   New note (signature)
  `<leader>nl`   Insert link
  `<leader>nL`   Link or create note
  `<leader>nh`   Link to heading (Org / Markdown)
  `<leader>na`   Add links matching regexp
  `<leader>nf`   Find outbound link
  `<leader>nb`   Open backlinks buffer
  `<leader>nB`   Find backlink (picker)
  `<leader>ng`   Grep notes
  `<leader>nu`   Unlinked mentions of the current note (quickfix)
  `<leader>nU`   Link the unlinked mention on the current line
  `<leader>nc`   Check for broken links & orphan notes (quickfix)
  `<leader>nqc`  Insert query-contents link
  `<leader>nqf`  Insert query-filenames link
  `<leader>ne`   Open Denote explorer
  `<leader>nr`   Rename file
  `<leader>nR`   Rename file from front matter
  `<leader>nk`   Add keywords
  `<leader>nK`   Remove keywords
  `<leader>nj`   Today's journal entry
  `<leader>nJ`   Link to today's journal entry
  `<leader>nC`   Journal calendar
  `<leader>nx`   Capture from a template (visual: capture the selection)
  `<leader>nz*`  Sequence commands (`p`, `c`, `s`, `f`, `r`, `l`)
  `<leader>nw*`  Silo commands (`c`, `o`, `e`)

Inside Org, Markdown, and plain text buffers, `<CR>` follows any `denote:`
link under the cursor and falls back to normal `<CR>` everywhere else.
`K` (`mappings.preview_link`) previews the linked note in a float and falls
back to LSP hover or the native `K` when the cursor is not on a link.
Press `g?` inside Explorer, Backlinks, or Query buffers for a keymap float.

7. ORG MODE (ORG.NVIM) & MARKDOWN                              *denote-syntax*

When `xheisenbugx/org.nvim` is installed, `denote.nvim` automatically hooks:
  - `org.config.opts.links.types.denote` (`follow`, `store`, `export`, `face`)
  - `org.dblock` writers for `denote-links`, `denote-backlinks`, `denote-files`

Pressing `<CR>` in an `.org` file follows `[[denote:ID][Title]]`,
`[[denote:ID::*Heading][Title::Heading]]`, `[[denote:ID::#custom-id][...]]`,
and live query links. `<leader>ols` stores a `denote:` link for the current
note, and `org.nvim` export converts `denote:` links for HTML, Markdown,
LaTeX, ASCII, and Org automatically.

In Markdown files, links default to `[Title](denote:ID)` (configurable via
`markdown_link_style = "denote" | "wiki" | "relative"`), and heading links
jump cleanly to matching `# Heading` slugs.

9. LUA API                                                        *denote-api*

`require("denote")` exposes every operation programmatically: >lua
  local denote = require("denote")
  denote.create_sync({ title = "Hello", keywords = { "lua" }, file_type = "org" })
  denote.rename_sync({ file = path, title = "Renamed", keywords = { "done" } })
  denote.follow_target("20261123T191500::#intro")
  denote.statusline() -- formatted note title for lualine / winbar
  denote.check({ quickfix = false }) -- { broken = {...}, orphans = {...} }
  denote.unlinked_mentions({ sync = true })
<
Long-running searches accept an optional callback and then run asynchronously,
returning a handle with `:cancel()`: >lua
  require("denote.backlinks").find(id, {}, function(matches) end)
  require("denote.query").search_contents("regex", {}, function(matches) end)
<

10. SEARCH, INDEX & PERFORMANCE                                *denote-search*

File index ~
Directory listings are cached per root. Each lookup re-checks only the mtime
of every scanned directory (adding, removing, or renaming a file changes its
parent's mtime), so external changes from git, sync tools, or Emacs are picked
up without rescanning every file. `:Denote reindex` drops all caches.

Identifier lookups (following links, broken-link checks) search the active
directory, every configured silo, and `journal.directory`.

Full-text search ~
Grep, query links, backlinks, unlinked mentions, and `:Denote check` share one
engine (`lua/denote/search.lua`):
  - `rg` is used when installed and `search.ripgrep` is true. It always runs
    with `--no-ignore --hidden`, so `.gitignore`d and dot-directories never
    hide notes, and results are filtered through the Denote file index.
  - Without `rg`, a pure-Lua scanner uses Vim "very magic" regexps (`\v`).
    Both dialects treat `| ( ) + ? {n}` as operators.
  - Case is "smart": insensitive unless the pattern has an uppercase letter.
  - Unsaved buffer contents are searched instead of the file on disk.
  - The Backlinks and Query buffers search asynchronously and show
    "(searching…)" until results arrive.

The statusline `%b` indicator is cached per note and refreshed in the
background (`search.backlinks_indicator_ttl`), so it never blocks redraws.

Run `make bench N=10000` to time common operations on a generated vault.

11. DIAGNOSTICS, PREVIEW & REPORTS                            *denote-reports*

Broken links ~
`denote:` links whose identifier cannot be resolved are highlighted with
`DenoteBrokenLink` and reported through |vim.diagnostic| (source `denote`,
code `broken-link`), so they appear in `]d`, |vim.diagnostic.setqflist()|,
and Trouble. Disable with `ui.diagnostics = false`. Checks are debounced
(`ui.debounce_ms`) after leaving insert mode, saving, or regaining focus.

Preview ~
`:Denote preview` (or `K` on a link) shows the target's title, identifier,
keywords, and first `preview.max_lines` body lines. Heading links start the
preview at that heading. Press `K` again to enter the float, `<CR>` inside it
to open the note, `q` / `<Esc>` to close.

Unlinked mentions ~
`:Denote unlinked_mentions` fills the quickfix list with lines in other notes
that mention the current note's title (case-insensitively) without linking
to it. Jump to an entry and run `:Denote link_mention` to wrap the mention in
a `denote:` link, keeping its original text as the description.

Vault check ~
`:Denote check` lists broken links (`W`) and orphan notes (`I`, notes no other
note links to) in the quickfix list.

12. JOURNAL INTERVALS & CALENDAR                              *denote-journal*

                                                     *denote-journal.interval*
`journal.interval` is "daily" (default), "weekly", "monthly", or "yearly",
matching `denote-journal-interval`. |:Denote-journal| reuses an existing entry
when the date in its identifier falls in the same period as the requested
date, and otherwise creates one. `:Denote journal_new` always creates.
`:Denote journal_link` links to the period's entry. Unknown values act as
"daily".

                                                   *denote-journal.week_start*
`journal.week_start` is the first day of the week for "weekly" and for the
calendar: 1 = Monday (ISO 8601 weeks, default), 0 = Sunday.

                                                 *denote-journal.title_format*
`journal.title_format` is an |os.date()| format for new entry titles, or a
table mapping an interval to a format. When nil (default) the per-interval
defaults are used:
    daily   "%A %e %B %Y"     weekly  "Week %V %G"
    monthly "%B %Y"           yearly  "%Y"
`%V` / `%G` (ISO week / week-based year) are expanded portably.

:Denote journal_calendar [{date}]                  *:Denote-journal_calendar*
    Open a floating month calendar on the month of {date} (default: today).
    Days with a journal entry are highlighted, as with Emacs
    `denote-journal-calendar-mode`. Keys:
        h / l          previous / next day
        k / j          previous / next week
        [ / ] or H / L previous / next month
        { / }          previous / next year
        t              go to today
        F or <CR>      visit the entry of the day at point (prompt if several)
        N              visit or create the entry for the period containing
                       the day at point (respects `journal.interval`)
        q / <Esc>      close
        g?             help
    Lua: `require("denote").journal_calendar({ date = "2026-11-01" })`
    Default global keymap: `<leader>nC`.

Highlight groups:
    DenoteJournalCalendarEntry    days with an entry (links to |hl-Special|)
    DenoteJournalCalendarToday    today (links to |hl-Todo|)
    DenoteJournalCalendarHeader   month title (links to |hl-Title|)
    DenoteJournalCalendarWeekday  weekday header row (links to |hl-Comment|)

13. CAPTURE TEMPLATES                                         *denote-capture*

:Denote capture [{key}]                                       *:Denote-capture*
:[range]DenoteCapture [{key}]                                 *:DenoteCapture*
    Create a note from a capture template, the Neovim analogue of Emacs
    `denote-org-capture`. Without {key}, pick one from `capture.templates`.
    With a range (visual mode `<leader>nx`) the selection becomes `%i`. A
    template with `target` appends to an existing note instead ("journal" =
    today's journal entry).

                                                       *denote-config-capture*
`capture` is a table with:
  - `specifiers`  Body used when a template has no `template`
                  (default "%l\n%i\n%?", like `denote-org-capture-specifiers`).
  - `templates`   A list of entries: { key, description?, template?, title?,
                  keywords?, file_type?, subdirectory?, signature?, date?,
                  prompts?, target?, open?, save? }. Fields left unset are
                  asked through the normal Denote prompts. `title` and
                  `signature` may contain escapes. `target` is "journal",
                  `{ identifier = ... }`, `{ path = ... }`, or a function
                  returning a path.

Example: >lua
  capture = {
    templates = {
      { key = "n", description = "Note" },
      { key = "m", description = "Meeting", title = "Meeting with %^{Who}",
        keywords = { "meeting" }, template = "* Agenda\n%?\n* Context\n%a\n%i" },
      { key = "j", description = "Journal", target = "journal",
        template = "- %U %^{Entry}\n%i" },
    },
  },
<
                                                      *denote-capture-escapes*
Escapes work in capture templates and in string `templates`:
  %^{Prompt}  %^{Prompt|default}  prompt (|vim.ui.input()|); reused by name
  %\N         answer of the Nth prompt
  %i          selected text / region       %x   clipboard (+, then ")
  %a  %l      link to origin (denote: link for notes, path:line otherwise)
  %f  %F      origin file name / full path %n   user name
  %t  %T      <2026-11-24 Tue> / <2026-11-24 Tue 16:30>
  %u  %U      [2026-11-24 Tue] / [2026-11-24 Tue 16:30]
  %?          cursor position after creation   %%  literal %
Lines containing only escapes that expand to nothing are removed. Not
supported: Org's `%^t` date prompts, `%<fmt>`, `%k`/`%K`, and choice lists in
`%^{P|a|b}` (only the first option is used, as the default).
